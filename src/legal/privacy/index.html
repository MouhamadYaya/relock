4. How we use personal data

We use the data described above to:

  • create and authenticate your account and maintain your session;
  • provide profiles, onboarding, blocking rules, on-device interventions, activity summaries, reminders, and account synchronization;
  • process, validate, restore, and manage subscription access;
  • personalize onboarding and understand subscription conversion using the onboarding attributes sent to RevenueCat;
  • diagnose crashes, app hangs, failed requests, and performance problems when crash reporting is enabled;
  • protect the service, prevent abuse, and comply with legal obligations; and
  • respond to support, privacy, and legal requests.

Where a legal basis is required, we rely on performance of our contract with you, your consent where the product requests it, our legitimate interests in operating and securing Relock where those interests are not overridden by your rights, and compliance with law. 6. On-device Screen Time and notification data

Relock uses Apple Family Controls, Managed Settings, and Device Activity capabilities. Apple provides opaque tokens for your app/category selections. The implemented design stores those tokens in the iOS App Group shared by Relock and its extensions rather than in Relock’s backend. Local shield-attempt records can include an application key/name and timestamp; Relock converts them into daily aggregate statistics before backend synchronization.

Reminders are scheduled as local device notifications. The audited code does not register for remote push notifications. Notification permission and individual reminder categories can be changed through the app and system settings.

7. Retention

The repository does not define complete time-based retention schedules. Unless a shorter period is confirmed, account-linked Supabase records remain until you reset the relevant activity or delete the account, subject to backups, legal obligations, and operational recovery processes.

  • Onboarding progress is stored locally during setup and cleared after setup completion.
  • Local shield event records are acknowledged and removed from the pending event log after aggregate synchronization succeeds.
  • Sentry’s on-device cache is configured for up to 60 events; this is not the same as Sentry’s server retention.
  • Each new profile photo uses a unique ImageKit file name. Automatic deletion of replaced photos is not implemented in the audited repository.
  • The in-app account-deletion function does not delete ImageKit assets or RevenueCat records.

8. Security

Relock uses authenticated Supabase sessions, row-level database policies scoped by user ID, HTTPS service endpoints, server-side privileged keys for account deletion, and short-lived signed ImageKit upload grants. Diagnostic events are configured to exclude default PII and are scrubbed for common secrets such as authorization values, tokens, email addresses, and phone numbers.

Some authentication tokens, preferences, onboarding progress, query cache data, and app state are stored locally using MMKV. The audited MMKV configuration does not set an application encryption key, so this Policy does not claim application-level encryption for that local data. No security measure is absolute, and we cannot guarantee that unauthorized access will never occur.

9. Your in-app controls

  • Profile: edit your display name, birth date, and profile photo.
  • Crash reports: disable or enable crash reporting in Settings. The current default is enabled when Sentry is configured.
  • Notifications: change reminder categories in Relock and notification permission in device settings.
  • Tracking authorization: use Apple’s system prompt or iOS settings to control tracking permission.
  • Reset activity: delete server-side blocking rules, daily statistics, and block-event rows while keeping the account and subscription relationship.
  • Export: export a JSON file containing profile, blocking rules, daily statistics, and up to 400 block-event and 400 daily-stat rows. This export does not currently include every local or provider-held dataset.
  • Delete account: delete the Supabase authentication user and cascading Supabase rows from inside Settings. This does not cancel an app-store subscription and does not currently delete ImageKit or RevenueCat records.
