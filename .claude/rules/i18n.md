# Rules — i18n

## Structure
- **One JSON file per locale:** `src/i18n/locales/fr.json`, `en.json`, `es.json`.
- Feature translations are **top-level sections** within each file — not separate files or namespaces (e.g. `auth.*`, `home.*`, `settings.*`).
- The section name must match the feature directory name, lowercase.

## Usage
```tsx
const t = useT()                  // no argument — returns t directly
t('auth.login.title')             // full dotted path: section.key[.subkey]
t('home.welcome', { name })       // interpolation
```
`useT()` is a thin wrapper around `useTranslation()` that returns `t` — it takes no namespace argument.

## Langue au démarrage
- La langue est **déduite du téléphone** (`react-native-localize` → `fr`/`en`/`es`, repli `en`) et retenue si l'utilisateur en choisit une à la main dans Réglages › Langue (`constants.PREF_LANGUAGE`). Tout passe par `src/i18n/i18n.ts` (`resolveInitialLanguage`, `setAppLanguage`) — ne jamais appeler `i18n.changeLanguage` seul, le choix ne survivrait pas au redémarrage.
- La langue est publiée dans le groupe d'app iOS pour les cinq extensions natives (`RelockLanguage.swift`), qui n'ont sinon accès qu'à la langue SYSTÈME.

## Filet automatique
- `npm run check:i18n` — **bloquant** (hook pre-commit + CI). Il refuse deux choses : un texte affiché en dur dans `src/` ou `app/`, et un écart entre `fr`, `en` et `es` (clé absente, valeur vide, valeur restée en français, `{{variable}}` perdue, clé orpheline).
- `npm run i18n:missing` — sort le français à traduire, clé par clé. `--out DIR` écrit `en.todo.json` / `es.todo.json`.
- `npm run i18n:merge -- <locale> <fichier.json>` — réinjecte les traductions. Refuse le lot ENTIER si une clé est inconnue du français, vide, ou si les variables ne correspondent plus : jamais d'écriture à moitié.
- Dans Claude Code, la skill `i18n-sync` (`/i18n`) enchaîne tout ça et traduit.
- `// i18n-ignore` (la ligne et la suivante) n'excuse que ce qui ne part PAS dans le binaire — une commande derrière `__DEV__`. Les fichiers entièrement de dev sont listés dans `NOT_SHIPPED` (`scripts/i18n-lib.cjs`).

## Clés calculées
- Hors composant (services, modules de calcul), utiliser `translate()` de `src/i18n/translate.ts` plutôt que `useT()`.
- `keepRemoved: true` dans `i18next-parser.config.cjs` n'est pas négociable : une grande partie du catalogue n'est atteinte que par des clés construites à l'exécution, invisibles pour l'extracteur.

## Images contenant du texte
- Une illustration dont le texte est dans les pixels se traduit par un fichier par langue via `localizedImage()` (`src/i18n/localized-image.ts`), jamais par `t()`.

## Must
- All user-facing strings go through `t()` — no hardcoded copy in JSX or styles.
- After adding or changing keys: run `npm run i18n:all` (extract + generate types).
- Add translations for **all three locales** (`fr`, `en`, `es`) — missing keys fall back to `en` but parity is required.
- Keep RTL layout in mind when adding new screens (avoid hard-coded `left`/`right` alignment).

## Must not
- Do not call `useT('namespace')` with an argument — the hook signature is `useT()`.
- Do not import translation JSON directly — use `useT()` / `t()`.
- Do not hardcode strings in `StyleSheet.create()` or component defaults.
